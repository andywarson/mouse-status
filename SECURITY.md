# Security policy

## Supported versions

Report issues against the latest published stable release. Before the first public release, use the current review candidate and include its commit when known.

## Reporting privately

Use **Security → Advisories → Report a vulnerability** when private reporting is enabled. If unavailable, request a private channel from the repository owner. Keep vulnerable input and sensitive details out of public issues.

Include the affected version, Windows version, expected and observed behavior, and a sanitized reproduction. Remove credentials, receiver or Bluetooth identifiers, personal paths, and private configuration from attachments.

The app stores preferences and history locally. A release checksum helps confirm file integrity. Authenticode signing is currently unavailable.
